# Compact Executive Gantt on Home — Phase C

The `/produtos` Home renders the compact Executive Gantt above the existing product cards. The chart requests the Phase B `executive-gantt` projection once per load for its portfolio data. Product management and individual schedule routes retain their existing requests and behavior. The component remounts and refreshes when a user returns from an individual schedule, and it also offers manual refresh. Workspace changes invalidate prior results before they can be shown; authentication and active membership remain enforced by the Worker.

Each product occupies one logical table row. Its stages are flattened only for placement: each bar retains the stable stage ID, discipline, original interval, and configured color. A deterministic greedy algorithm assigns the first available lane, treating date boundaries as inclusive. Fully undated stages remain in an identified count on their product row; a stage with one known boundary is a dashed marker at that civil date, without an invented duration. Product-root activities affect the product range shown beside the name and timeline extent, but are not stage bars.

Phase C.1 fixes every desktop product row at 80 px. Only the first two packed lanes render individual bars. Further stages form deterministic groups in a third, compact overflow track based on rendered interval overlap; a product-level count also remains visible when the track is horizontally offscreen. Both indicators open a keyboard-accessible detail dialog containing every additional stage, its discipline, exact civil dates, and configured color. Fully undated stages are included in the product-level dialog. Short stages receive a minimum 28 px badge labeled with their stage code; packing reserves this visual width so adjacent badges cannot silently overlap. The original intervals and dates are unchanged.

The chart uses the existing civil-date timeline utilities. Month is the initial scale; week is available. Month/year and week tick headers, a current-date line, sticky product names, synchronized row hover, weekend and established calendar-rule shading, and workspace calendar exceptions follow the existing Gantt conventions. Calendar exceptions use the current read-only workspace calendar endpoint for supported years. Milestones are grouped by product and civil date; each cluster shows colored diamonds, a count for collisions, and a detail list preserving each name and color. Archived products are identified and can be hidden without changing the API result. Milestones can be hidden independently.

The **Abrir cronograma executivo** action is visible but disabled until Phase D supplies its destination. The compact chart remains a read-only view of current working schedules. It does not select revisions or scenarios, modify schedule dates, or alter R00.

Phase C.1 uses the existing `workspace-zoom` segmented-button styling for the week/month scale. On desktop, scale, archived visibility, milestone visibility, refresh, and the primary full-view action share one 32 px toolbar. At widths of 54 rem or less the toolbar wraps without stretching its scale control. The refresh button is secondary; Phase D enables the full-view action at `/produtos/cronograma-executivo`. The individual product Gantt styles and behavior are unchanged.
